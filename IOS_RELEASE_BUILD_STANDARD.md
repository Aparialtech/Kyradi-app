# Kyradi iOS Release Build Standard

## Purpose
Deterministic TestFlight/Release builds that always include `API_BASE_URL` and never ship with missing config.

## Single Source of Truth
- `API_BASE_URL` must come from `--dart-define`.
- Any build without `API_BASE_URL` must fail in Release (enforced by the Xcode build phase script).

## Release IPA Build (single correct command)
- `flutter build ipa --release --build-number=<N> --dart-define="API_BASE_URL=https://kyradi-app-production.up.railway.app"`

## Build Number Rule
- Build number must always increase.
- Use the last uploaded TestFlight build number + 1.

## Upload Checklist (Transporter)
- Confirm `API_BASE_URL` is set in the build command.
- Confirm build number is higher than the last uploaded build.
- Upload the produced IPA via Transporter.

## If “API configuration missing” appears
- The IPA was built without `API_BASE_URL`.
- Rebuild using the standard command above.

## Generated File Policy
These files are generated by Flutter and must not be tracked:
- `ios/Flutter/Generated*.xcconfig`
- `ios/Flutter/flutter_export_environment*.sh`
- `ios/DART_DEFINES`

## Xcode Project Guard
- `DART_DEFINES` must not be hardcoded in `project.pbxproj`.
- Release builds run `ios/scripts/verify_dart_defines.sh` to enforce config.
